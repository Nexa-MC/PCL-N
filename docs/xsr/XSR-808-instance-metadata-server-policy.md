# XSR-808 — 实例信息和服务器环境策略

2026-10-08（Asia/Shanghai）。实例信息编辑保留 schema 1 和已有字段默认值，追加稳定
identity、显示名称、标签、分组和备注。显示名称不改变实例目录/版本 ID；物理改名
仍使用已有恢复事务。修改以元数据文件 SHA-256 为乐观版本，不覆盖陈旧草稿；
共享 metadata store 串行化更新并保留启动计数及未编辑的已有属性。

编辑器提供图标、描述、收藏、Custom Info、标签、分组、备注及默认服务器。
同实例、同已读取 metadata revision 的非导航重建保留未保存文字、备注页和布尔
选择，包括离线查询及 management 查询完成；草稿仅存于当前 UI，不执行保存。
实例切换、页面导航、显式重新读取和成功保存后的新 revision 不重放旧草稿。
图标来源为用户指定的本地完整 PNG 路径，有界解析；不执行/下载用户图标。
完整根和实例身份必须位于 versions 下，路径不得经过链接。损坏、超大或未知
schema 的现有元数据明确拒绝写入，不以默认值覆盖。
JSON 显式 null 的受管文字、集合及集合元素视为损坏数据；typed query 在使用
字段前检查形状和大小，返回可诊断错误，保存时同样保留原损坏文件。缺省字段仍
使用 schema 1 的默认值，便于已有实例逐项迁移。
JSON 读取保持既有 camelCase、大小写敏感规则：只有 canonical 字段参与读取和形状
校验，其他大小写的未知字段不会冒充 canonical 字段，也不会修改原文件。canonical
字段显式出现的 0、未知 schema 或 null 不作为缺省值补齐；CorePatchSha256 的既有
null-to-empty 兼容例外保持不变。
所有现有 MinecraftJsonContext 消费者通过同一内部 converter 读取：对 bounded JSON
对象仅补齐未出现 canonical 字段的 schema 1 默认值，再交给独立 source-generated
wire context 反序列化；显式值和未知字段原样参与解析，不在磁盘保存归一化副本。
这样避免 NativeAOT sourcegen 的 init-only 初始化路径以 CLR 0/null 覆盖 record 属性
默认值；实例信息、库/启动、离线检查和协议读取获得相同默认值。公开 record、JSON
输出字段与 schema 1 不变，损坏数据和显式未知 schema 的严格拒绝保持不变。
库发现使用有错误标记的只读展示快照：损坏实例仍可定位，但显示“实例信息不可用”。
普通 metadata 读取、写入和启动准入使用严格形状/schema/512 KiB 检查；错误标记
禁止启动，Save/Update 不覆盖原损坏文件。展示默认值不会进入启动准入，也不会
因此放宽服务器约束、制品验签或真实性检查。

服务器登录约束沿用 dev 的 0 不限 / 1 Microsoft / 2 第三方认证 / 3 两者之一。
第三方必须匹配声明认证 endpoint，认证配置锁定时不得通过编辑器改变登录约束。
离线档案准入独立于 Java 兼容、制品完整性和认证有效性；关闭离线档案只会收紧
准入，不授予已有 online token 绕过认证的能力。

Environment Match 使用用户声明的游戏版本、加载器和必需模组 ID 与本实例事实
对照，不伪称从服务器获得未知信息。若声明了要求，启动前必须匹配；无法完整
读取模组清单时不能宣称匹配。实例信息页与启动阶段使用同一个 current manifest
加载器 detector，避免安装器的附加组件排序或 LegacyFabric 命名产生不同事实。
声明认证端点无效、账户类型不符或环境不符均拒绝
启动，说明具体原因。Java 和制品安全检查始终强制，不开放无消费者的关闭开关。

验证覆盖持久化、陈旧版本/损坏数据拒绝、认证锁、账号类别/端点、离线策略和
环境一致性，以及真实服务路由的编辑器入参。最终构建与原生发布由根任务记录。
